# rclc/rclcpp

1. common
- 포인터 선언 시 *<변수명>, 주소 복사 선언 시 &<변수명> 으로 무조건 통일.
e.g. before) * options, after) *options

- const &<변수명> 복사 적극 활용

- auto 사용 최대 지양.
type 기재 가능하면 전부 기재.

- 함수 선언/호출 시 개행 사용 최대 지양.
e.g. Pose2D refine_pose_with_scan_matching(const sensor_msgs::msg::LaserScan &scan, const Pose2D &predicted_pose) const
로 사용.

- tab indent는 BSD style로 통일
e.g. if, for, 함수 등등 전부 개행 이후 {} 시작.
e.g. hpp
namespace slam::mapper
{
    class SlamMapper
    {
    private:
    protected:
    public:
    };
}

e.g. cpp
namespace slam::mapper
{

SlamMapper::SlamMapper()
{

}

}  // namespace slam::mapper

2. repository workflow
- 작업 시작 전 `README.md`, `TODO.md`, `CHANGELOG.rst`, `coding_template.txt` 를 먼저 확인.
- 구조/책임/인터페이스가 바뀌면 `README.md` 먼저 갱신.
- 우선순위/실험축이 바뀌면 `TODO.md` 갱신.
- 브랜치 시작, 의미있는 milestone, release성 변경은 `CHANGELOG.rst` 기록.
- user-facing topic naming 은 기본적으로 `/slam/*` 를 기준으로 설계.

3. hpp
- namespace 는 `slam::<category>::<actor noun>` 또는 필요한 경우 `slam::<actor noun>` 로 통일
e.g. `slam::mapper`, `slam::graph::optimizer`, `slam::scan::matcher`

- #include 시 외부 header는 <>로, custom header는 ""로 wrapping
e.g. <cstdint>, <rclcpp/rclcpp.hpp>, <geometry_msgs/msg/twist.hpp>
"slam_mapper/slam_mapper.hpp"

- 생성자에는 explicit, 소멸자에는 virtual 무조건 기재.

- class 구성 시 순서는 private, protected, public 순으로 통일.
e.g. private: ..., protected: ..., public: 생성자, 소멸자 ...

4. cpp
- #include 는 무조건 #include "package/<pair되는 hpp>" 만 하고,
나머지 외부 header는 전부 pair.hpp에서 처리.
e.g. #include "slam_mapper/slam_mapper.hpp" 한줄만 있어야함.

5. SLAM direction reminders
- front-end 와 back-end 책임을 섞지 말 것.
- front-end 는 motion prior, scan alignment, local correction 품질에 집중.
- back-end 는 keyframe, graph edge, loop acceptance, optimizer correction 품질에 집중.
- false loop closure 방지는 recall 향상보다 항상 우선.
